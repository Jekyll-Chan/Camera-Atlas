# Actual rendering workflow

1. Inspect real input files with the trusted engine `camera_atlas.image.io.read_photo` to obtain normalized dimensions, orientation and available EXIF GPS. Use an actual vision/image-viewing tool for composition judgments; Python decoding alone is not image understanding. Retain originals.
2. Resolve location: explicit user correction wins over conflicting EXIF. Never reinterpret the center of a lake/city as camera GPS. If an exact camera coordinate is known, pass `--lat/--lon`. If only a place is known, use a trusted geocoder or a sourced offline `location` with accuracy `locality`/`regional`. Consult geography.md and ask only when identity is ambiguous.
3. For a sourced locality when no geocoder is configured: create a small RFC7946 FeatureCollection with empty `features`, a source record and a `location`. Record the actual reference URL/date, dataset/version/license/credit, `source_id`, verified coordinates, `coordinate_source` and accuracy. Do not guess coordinates from model memory. Passing `--geojson` then permits the engine to request bounded OSM geometry online around the declared locality. A metadata-only locality file is not itself map geometry. If network is unavailable, actual offline geometry is required; otherwise return a clean base or a plan.
4. Do not enable public Nominatim or paid services on the user's behalf. For public-provider restrictions see geography.md. Map inputs must cover the correct region. Terrain mode requires an actual georeferenced DEM and source declaration. Never reuse demo lake geometry for a different photo/location.
5. Use auto mode/editorial-minimal, default opacity and unobtrusive placement unless asked otherwise. Check negative space visually; add a normalized-size exclusion mask for important subjects when needed. The built-in saliency is a texture heuristic and cannot reliably recognize people or peaks.
6. Run the installed engine with a new output directory, independent layers enabled, optional SVG. If the user asks to restyle a previous render, reuse `clean_base.png` and exported `location.geojson`, with text repair off.
7. Read metadata/provenance and inspect actual outputs. If overlay coverage is zero, explain that no verified map was drawn. If the image cannot be inspected with vision, state that automated pixel checks passed but visual review is pending. Never claim to have seen a file that a tool did not show.
8. Return the usable final image, transparent layer and source report in that order. Describe source precision in everyday language and mention only material warnings. Do not publish user photography/GPS or move it into a public demo/repository.

All required source record fields and supported kinds are in geography.md. Source declarations are auditable claims, not independent certification. Users should not be asked to hand-author GeoJSON, select a projection or obtain an API key for the normal vector path; the agent handles those steps from verified data. If the necessary tools are absent, Plan mode is an honest deliverable.
