## 用户只做两件事

提交照片和地点，领取成品。普通用户无需安装 Skill、Python 或 GIS 工具，无需拥有 GitHub/Agensi 账户，无需提供模型密钥。

默认入口是一张简洁表单：Photo、Place、Create。地点候选在同一页面确认。后台自动准备地图区域、扩展地理范围、取得地图、合成与检查；页面显示 Processing，完成后出现照片与 Save。Edit 是可选修改入口，不要求每个用户先手工涂选。保留全英文、衬线字体、克制动效和当前联系邮箱。

只有地点有歧义、选区可信度低、截图修复需要审阅或数据不足时，才就地请求一个必要补充。不得以静默猜测地点、遮挡主体或重画原照片换取表面上的全自动。

## 后台的真正工作

1. 接收并保存原文件，建立不可变干净底图。默认不重新生成照片；截图清洗是独立可选步骤。
2. 解析并确认地点，保留地区/真实 GPS 的精度区别。
3. 自动建议整片天空、水面或其他负空间，并保护人物、建筑和树枝；低置信度转到可修改预览。不能用固定 Top/Right 矩形冒充识别。
4. 按选区比例扩展真实地图窗口，检查取数范围和解析完整性。获取不足时补取或明确失败，不拉伸、重复、编造地物。
5. 由确定性渲染器绘制独立透明地图并合成，检查原图保护、真实几何和来源。
6. 保存与输入版本对应的原尺寸成品，生成可恢复的私有结果页和下载。

AI 负责识别与建议，制图程序负责真实地理、像素保护与输出。普通照片的主链路不调用“整图重生成”；因此无需为每张照片支付一次整图生成费用，但识别、地图数据、运行与存储仍可能产生费用。

## 平台分工

| 平台 | 用途 | 不承担的环节 |
| --- | --- | --- |
| GitHub | 源码、版本、测试、构建和发布部署 | 不保存用户照片；不把 Actions 当公众图片加工队列 |
| Agensi | 已有 Skill 的发现入口；将来可通过适配器调用同一应用服务 | 不等于已托管 Camera Atlas 渲染器，不作为普通网页访客必需的登录步骤 |
| Python 托管服务 | 接收请求、排队、制图、状态查询和交付 | 不依赖开发者电脑一直开机 |
| 私有文件存储 | 原图、蒙版、成品和有限期下载 | 不放进公开仓库或可枚举的公开图库 |

GitHub Pages 是静态托管，无法直接运行本项目的 Python 内核：[官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。GitHub 的 Actions 使用条款也限制将它作为无服务器应用或运行与软件开发/测试/部署无关的任务，因此本方案只用于项目测试和部署：[条款](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#actions)。

Agensi 的 Skill 在用户 agent 的工具环境中执行；其工具任务机制可以借鉴，但没有证据表明上传本项目 Skill 就会获得 Camera Atlas 云处理能力：[工作方式](https://www.agensi.io/docs/how-it-works)、[工具接口](https://www.agensi.io/docs/tools)。

## 建议的首个托管形态

首个小流量试用版采用一台支持 Python 的托管应用：成熟的 HTTP 服务适配器 + 有界处理队列 + 持久文件/数据库。同一服务交付前端与接口，降低初期配置量。当前 `http.server` 本机预览不能直接解除绑定限制后用于公网。

可选用 Render 这类能从 GitHub 部署 Python 服务的平台；其后台 worker 面向耗时任务，服务可跟随代码自动部署。现有 SQLite 与本地文件仅适合一个持久工作目录和一个工作进程。若拆成多个服务，任务数据库与文件必须改为共享存储，不能让各服务各自读取本地 SQLite。[部署说明](https://render.com/docs/deploys)、[后台 worker](https://render.com/docs/background-workers)。

Render 默认文件系统是临时的，使用磁盘方案需要付费服务与持久磁盘；不能把默认目录当永久结果库。[持久磁盘说明](https://render.com/docs/disks)。这里只提出候选方案，尚未开通账户、创建服务、购买资源或承诺零成本。实际规格由样片峰值内存、并发与耗时测试确定。

上线时采用匿名会话与私有结果凭证，用户无需注册。凭证不能等同于公开可枚举的任务 ID。限制文件体积、排队数量和访客请求速率。建议初期文件保留 24 小时并明确显示到期时间；该生命周期尚未实现。默认在结果页交付，邮件通知作为未来可选功能，当前不采集邮箱或发送邮件。

## 本轮已经实现

- 本地持久任务队列：queued / preparing / rendering / verifying / ready / failed。
- 上传原文件、规范化底图和成品保留在工作目录，服务重启后可重新找到。
- 同一请求键避免重复提交；有界队列和单目录独占 worker，防止重复处理。
- 渲染前验证地点、选区尺寸和透明度，完成后才登记可下载结果。
- 刷新页面恢复最近任务及其输入；失败时 Retry 复用原输入，不要求重传。
- 中断的运行任务标为可重试失败，未开始任务留在队列；不谎报完成。

这是一台电脑上的真实后台闭环，仍只有两个样例地点与手动选区。ready 表示结果文件已经生成，不表示地图范围已通过全球数据覆盖或人工美学验收。尚未部署公众服务、完成自动选区、接入任意地点或实现多访客隔离。

## 下一阶段的上线门槛

1. 取得自动选区与地点/地图提供器的可用配置，完成图片识别→真实地图→原尺寸输出的联调；需要外部服务时由运营方配置，不把密钥交给访客。
2. 用东京站、八坂神社、十七孔桥和赛里木湖等非内置地点验证：整片区域铺满、主体保护、地名歧义、缺数据与超时恢复。
3. 加入公众 HTTP 适配器、匿名会话隔离、结果凭证、限额与文件到期清理，部署到云后台。
4. 用未安装任何工具的真实手机，从公开链接上传新照片和地点，自动得到并下载正确成品。此项成功前不能宣传“点开即用、人人可用”。
